# HyperIDs dataset 目录规则

本文件覆盖 `/home/ubuntu/Works/hyperids/dataset` 及其子目录。它补充根 `AGENTS.md`，并优先约束本目录内的数据操作。

## 1. 默认原则

- 数据集是训练和评测资产，不是对抗生成器的“答案库”。
- 默认工作模式是只读分析：统计、校验、去重、哈希、分片审计和 schema 检查。
- 修改、合并、重切 split、生成新训练数据或删除样本，必须先得到用户明确授权，并另建数据构建任务。
- 不把重要产物写到 `/tmp`；产物放在仓库内版本化目录。

## 2. 禁止读取和禁止泄漏

以下路径对生成器、变异器和报告草稿代理默认不可读：

- `dataset/gliclass_v2/train.json`
- `dataset/gliclass_v2/val.json`
- `dataset/gliclass_v2/test.json`
- 任何训练语料、软标签、标签缓存、预测缓存或私有数据
- `dataset/private/**`
- 包含密钥、token、凭据、内网主机名或个人信息的文件

要求：

- 不得把 `test` 或 `val` 样本改写后放入对抗集，再声称是独立发现。
- 不得从软标签、模型预测或已有评测结果反推“真值”再写回样本。
- 不得让对抗样本自动进入 `train.json`、`val.json` 或 `test.json`。
- 报告必须明确声明是否读取过训练语料；默认声明“未读取”。

## 3. 允许的只读工作

在用户要求数据审计时，可以读取并统计：

- split 数量、字段完整性、重复率和类别/action 分布；
- schema、标签定义和公开规则文件；
- 文件 SHA-256、编码、换行符、坏样本和空样本；
- 数据来源和 provenance 字段；
- 已冻结的公开评测报告。

统计结果可以写入新的、带版本号的分析目录，但不得覆盖原始数据。

## 4. 数据构建任务

只有用户明确要求构建训练数据时，才可写入数据集。此类任务必须：

1. 先定义来源、目标标签、split 策略和验收标准；
2. 对每条样本记录来源、生成/转换方法、时间戳和父样本；
3. 做原始命令 SHA-256 与规范化比较键去重；
4. 在 train/val/test 之间做精确和近重复泄漏检查；
5. 人工或独立规则复核，不能以模型预测当标签；
6. 将对抗样本与普通训练样本分开记录；
7. 保留随机种子、脚本版本和可复现命令；
8. 不覆盖历史 split；新版本使用新目录。

## 5. 良性控制集

- 控制集必须独立于训练、验证和测试集。
- 控制集要记录来源和允许读取的目录。
- 不得用模型认为“良性”作为唯一真值。
- 计算 Precision/FPR 前先验证控制集与已冻结 split 无重叠；否则只能报告 `N/A` 或 exploratory 结果。

## 6. 禁止事项

- 不执行、不 `source`、不 `eval` 数据集中的命令文本。
- 不下载数据中出现的载荷、二进制或外部脚本。
- 不写入真实 IOC、凭据或个人信息。
- 不把 `dataset/private/**` 的内容复制到报告、日志或对抗集。
- 不把测试集指标包装成生产泛化指标。
- 不自动提交 Git。
